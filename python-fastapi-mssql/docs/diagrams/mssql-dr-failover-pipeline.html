02 · Two modes, one command each

Planned vs forced

The task file picks between these based on the mode query param — and refuses a planned failover outright if the precondition isn't met.

Planned failover

safe · zero data loss
mode=planned
ALTER AVAILABILITY GROUP [AG1] FAILOVER
Precondition
Target must already report SYNCHRONIZED — checked via synchronization_state_desc before the command runs.
If the precondition fails
Ansible's fail: module stops the run immediately with a message pointing at mode=forced — nothing destructive is attempted.
Use when
Both replicas are healthy and reachable — a controlled maintenance handoff, e.g. patching the current primary.

Forced failover

risk · possible data loss
mode=forced
ALTER AVAILABILITY GROUP [AG1] FORCE_FAILOVER_ALLOW_DATA_LOSS
Precondition
None enforced — this mode exists specifically for when the sync-state check itself can't be trusted.
Risk
Any transaction committed on the old primary but not yet shipped to this replica is lost. Acceptable trade for getting a primary back.
Use when
The current primary is down or unreachable and a primary is needed immediately — there is no AG listener and no automatic failover in this lab, so this call is the failover mechanism.
